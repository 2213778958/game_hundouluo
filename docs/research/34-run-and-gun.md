## 大佬作品在做什么

NES Contra 八关（街机十段，基地核心并进关底）：Jungle、Base 1、Waterfall、Base 2、Snow Field、Energy Zone、Hangar、Alien Lair。每一关的**地形任务**不同，不是同一条平地换皮肤。

敌人按编号分职，不是同一套「巡逻 + 水平射击」改血量：

| 编号 | 名 | 可见差异 |
| --- | --- | --- |
| 05 | Soldier | 跑；属性位决定是否开枪、到沿是否掉头（最多掉头 2 次）或走下沿 |
| 06 | Sniper | 站住；朝任意方向打；可站着连打或蹲藏再打 |
| 07 | Red Turret | 靠近才升起；玩家走过并卷出屏幕后缩回 |
| 16 | Jumping Soldier | 边跳边穿屏，和地面士兵不是同一 routine |

户外关清关**不是**杀光士兵。士兵会从屏边生成（Enemy Routines）。Jungle 要打到关底要塞并毁掉 power core；Base 要清房间 core 再打关底；Waterfall 要 hop 上台阶爬到顶再打关底。台阶是一串能一跳上去的沿，不是一个够不着的高台。TAS 记录里，Waterfall 个别够不着的沿要靠卷轴 glitch，说明**正常设计按一跳可达**。

玩家水平速度每帧清零再写入，落地即停；空中按方向会保持水平动量。从沿上落下或下钻平台时，先忽略脚底碰撞约 20px（略大于一格），保证能落到下一层而不是卡在当前沿里。

本游戏是单屏短三关，不抄无限刷兵、不抄要塞 core、不抄原声、不抄军装。下面把这些原则收成三关能执行的数。

## 本游戏对照快照（b4629f8，只作缺口说明）

`player.gd`：`JUMP_VELOCITY = -320`，`GRAVITY = 900`。理想跳高 `v²/(2g) = 56.89`px。离散积分更矮。后文 `max_rise` 按实际两常数算。

`stages.gd` `_layout`：

- 平地练手：长 640，2 只同模杂兵（x=280 / 460），各巡逻 ±36，无高台。
- 高台掩体：高台顶 y=220 与 y=176（相对地板顶 300 要升 80 / 124）；掩体高 64；5 只同模杂兵，其中 2 只站在玩家跳不上去的台上。
- 通道头目：长 420 短通道，1 头目。头目与杂兵共用 `fire()`，差在血、冷却、站住。

`is_cleared`：布置过敌人且活敌为 0。#28 主机套件在树外证明「留一只活着不切关」，但套件不跑 `ClearWatcher` 物理帧，也不断言进树后第一帧 `living == grunt_count`。

## 现象 1：关卡设计不合理

### 大佬

关卡按任务分段：先练走打（Jungle 前段平路 / 浅水 / 少量沿），再上多层沿，最后关底结构。每一段换地形任务，不换皮。

### 本游戏缺口

合同只写「平地杂兵 / 高台掩体 / 短通道头目」，没有遭遇间距、台阶、关底条件。现状是一屏里两只同模雕像，第二关把人放上跳不上去的台。

### 后续票必须遵守

三关名字与顺序不变。每一关只改写死布局，不接编辑器，不增第四关。

**平地练手**

- 地板连续，0 高台，0 掩体，0 头目。
- 布局杂兵 ≥ 3，或恰好 2 只但水平间距 ≥ `RUN_SPEED * 1.5`（按 `player.gd` 常数，现为 210px）。现 180px 两只雕像不算分段遭遇。
- 相邻布局杂兵的站位 x 差 ≥ 168px（`RUN_SPEED * 1.2`）。玩家必须走一段再遇到下一只。
- 清关条件走现象 4，不靠走到右边界。

**高台掩体**

- ≥ 2 块高台，≥ 2 块掩体，杂兵数 > 平地练手。
- 高台必须是台阶：从地板或更低固体出发，每一级顶面升高 ≤ `max_rise`（现象 3）。禁止「只有一块够不着的高台」。
- 掩体是挡水平弹的矮块，不是墙。掩体高度 ∈ `[player 碰撞高, max_rise]`（现碰撞高 22，故约 22–48）。玩家能站在掩体左侧或右侧地板上。掩体不得挡住通往任一高台的唯一落脚点。
- 地板上至少 1 只**游走**，高台上至少 1 只**哨位**（现象 2）。台上的哨位所在高台必须一跳可达。
- 火力更密 = 同时在场的职责种类 ≥ 2，且杂兵数多于第一关。禁止只复制同模巡逻。

**通道头目**

- 短通道：长度 < 平地练手，有顶有尽头墙，0 额外高台。
- 尽头恰好 1 头目。可选 0 或 1 只哨位；有哨位也不代替打倒头目。
- 清关条件走现象 4。

后续 stages 票的主机测试只验机制（数量、间距、`max_rise`、清关计数），不验好不好玩。

## 现象 2：怪物行为都一样

### 大佬

士兵 / 狙击 / 炮台 / 跳兵是不同 type 与不同 routine。头目是另一套行为，不是更大号士兵。

### 本游戏缺口

`CONTEXT.md`「会走会射即可」被读成全员同一 `configure_grunt` 巡逻。头目只改 HP / 冷却 / 站住，观感仍是「大杂兵」。

### 后续票必须遵守

只保留三种职责，不新开第六个模块，不抄军装与原版精灵。外形继续未来士兵或无人机 + 霓虹。

| 职责 | 谁用 | 进树后必须能被玩家分辨（不开枪也成立） |
| --- | --- | --- |
| 游走 | 平地练手全部；高台掩体地板 | 在 `patrol_min_x..patrol_max_x` 走动，路宽 ≥ 120px（现 ±36 不算走）。到沿掉头，不走出关卡边界。 |
| 哨位 | 高台掩体至少 1 只；通道可选 1 只 | `patrol_min_x == patrol_max_x`，站在可达高台或通道侧面。每帧 `face_toward` 玩家。不沿台来回走。 |
| 头目 | 仅第三关 1 只 | 体型与残骸纹理大于杂兵；站住；血量 > 任一杂兵。打倒才通关第三关。 |

人审说过本闸门可以暂不做怪物攻击。职责差必须靠走 / 站住 / 位置 / 体型成立。若某张后续票打开敌弹：游走只打水平；哨位朝玩家；头目冷却短于杂兵。不得三职共用同一套水平弹参数。

禁止：全部杂兵同一巡逻宽、同一站住、同一朝左；头目复用杂兵走动。

`hostiles` 用 `role` 或 meta `duty` ∈ {`runner`,`sentry`,`boss`} 标出来。`stages` 按关卡槽位调用不同 configure。不要为了差异化去重开 #26 原文。

## 现象 3：高台关卡玩家根本上不去

### 大佬

Jungle「series of ledges. Jump to the top」：沿是台阶。玩家能落到下一层（下钻约 20px 忽略脚碰）。正常沿不靠 glitch。

### 本游戏缺口

合同只要求「有高台节点」，没要求玩家能站上去。现跳高约 57px，最低台要升 80px，中间台 124px，掩体顶 64px。全员够不着。台上还站了杂兵。

### 后续票必须遵守

从 `player.gd` 现用常数计算，禁止写死与代码脱节的像素：

```
jump_height = JUMP_VELOCITY * JUMP_VELOCITY / (2 * GRAVITY)
max_rise = floor(jump_height) - 8
```

现为 `floor(56.89) - 8 = 48`。改跳跃必须重算高台。

**一跳可达**：从一块站立顶面（地板顶或已达高台顶）到下一块**必达**顶面，升高 ≤ `max_rise`，水平间隙 ≤ `RUN_SPEED * 0.35`（现 49px），否则中间必须再插一块同样满足本式的台。

第二关每一块 `stage_part=platform` 都是必达：玩家从出生点只靠走和地面起跳，能站上每一块高台顶。台上有哨位则该台必达。

禁止：升高 > `max_rise` 的孤台；把 64px 掩体当唯一台阶（现掩体 64 > 48）；用二段跳、墙跳、弹簧、传送。

高台是能落到脚底的固体（从下跳上可穿、落下可站，或普通实心但台阶高度合法）。本票不验手感，后续票用几何不等式验收，不靠「觉得跳得动」。

优先降台 / 加台阶，不动跳跃常数。若改 `JUMP_VELOCITY` 或 `GRAVITY`，三关固体全部按新 `max_rise` 重算。

## 现象 4：第一关杀一只怪就切下一关

### 大佬

杀一只士兵不切关。户外士兵可生成。真正切关是关底结构（core / 关底敌）或爬到顶。

### 本游戏缺口与缺陷

产品已是短三关有限布局，不引入无限生成，也不改成「碰到右门就过」。#28 把「打完」收成 `living == 0`，没写：

- 进树就绪后，活敌必须等于布局槽位数；
- 必须分别打倒每一个布局槽位；
- 杀 1 只、其余仍活，禁止切关。

树外测试写过「留一只不切」，但人不在树外玩。人看见杀一只就切，说明运行时就绪活敌可能已经 < 布局数，或 `ClearWatcher` 在仍有活敌时切了。前者是合同没写就绪计数，后者是实现没守测试原意。

### 后续票必须遵守

**就绪存活**：`go_to_stage` 之后、玩家第一次开火之前，`living_hostile_count == layout_slots`。`layout_slots` = 该关 `grunts` 条数 + （有头目则为 1）。任一关 `layout_slots < 1` 视为布置失败。平地练手 `layout_slots` 必须 ≥ 现象 1 的杂兵下限。

**分别打倒**：`is_cleared` 为真仅当（1）就绪存活曾成立，且（2）每一个布局槽位都变成不可再造成伤害的死（`alive == false` 或等价），且（3）当前活敌为 0。杀 1 只、其余仍活，必须保持本关，禁止 `go_to_stage`。

各关清关：

| 关 | 清关 |
| --- | --- |
| 平地练手 | 全部布局杂兵分别打倒。0 头目。 |
| 高台掩体 | 地板游走 + 台上哨位全部分别打倒。0 头目。台上不可达导致打不到，算现象 3 未完成，不算清关。 |
| 通道头目 | 打倒那一只头目。通道里若有哨位，打倒哨位不切关、不代替头目。头目死后停在第三关，不造第四关。 |

禁止：走到右边界切关；`defeated` 第一声就切关；用「曾经布置过、现在活着是 0」绕过就绪存活（一只怪生成失败再杀另一只，必须仍算未清）。

后续 stages 主机测试至少覆盖：就绪存活 == 布局数；杀 1 只不切；杀完全部才 `go_to_stage(2)`；第三关只在头目死后通关。可以驱动 `ClearWatcher` 物理帧。仍不验手感。

## 现象 5：还有 bug（缺口还是缺陷）

「还有 bug」里混了两件事。后续票必须先标类型再改。一种票不要同时改两类。

### 合同缺口（先改合同，再开实现票）

人审五条里，前四条在 #26/#27/#28 原文里都没有可执行数。继续按原文改，只会再出新现象。

| 现象 | 缺口 | 后续写进哪 |
| --- | --- | --- |
| 关卡不合理 | 无遭遇间距、无台阶、无职责布置 | stages，遵守现象 1 |
| 怪物都一样 | 「会走会射」无职责差 | hostiles + stages 槽位，遵守现象 2 |
| 高台上不去 | 「有高台」≠ 玩家能站上去 | stages 几何 + 必要时 player 常数，遵守现象 3 |
| 杀一只切关 | 「打完」无就绪存活、无分别打倒 | stages 清关，遵守现象 4 |

这些不是 #14 / #24 / #29 的回归。不要重开那三张。不要把缺口写成「再调一调 #28 原文」。

### 实现缺陷（合同已有，实现没守）

人审已经收过、或测试原意已经写明的，才算缺陷：

| 已有合同 | 若再现 | 去哪 |
| --- | --- | --- |
| 怪被打倒后看得出死了 | 仍僵站当活的 | #26 那条线，只修死亡可见 |
| 入口 / 选枪 / 血条不要只有黑底灰块 | UI 回退 | #27 那条线，只修 boot 表面 |
| 树外「留一只活着不切关」 | 进树后杀 1 只仍切，且就绪存活其实已是 2 | stages 清关实现，但验收按现象 4 重写，不按 #28 原文 |
| 开火与跳跃不抢键；玩家弹能打中；不走出地图 | 人说「差不多了」之后又回退 | 已有 #21/#22/#23 合同，不新造玩法 |

实现缺陷的票只修违约行为，不顺便改布局、职责、跳高。

### 怎么分开处理

1. 规划票正文引用本文对应现象，写出数（间距、`max_rise`、职责、就绪存活）。禁止只写「做好玩一点」「对照大佬再改」。
2. stages 实现票：现象 1、3、4。allowlist `stages/` 与 `tests/stages/`。
3. hostiles 实现票：现象 2 的职责。死亡可见仍是 #26，不并进职责票。allowlist `hostiles/` 与 `tests/hostiles/`。
4. 只有改了 `JUMP_VELOCITY` / `GRAVITY` 才动 `player/`。默认不动。
5. boot / audio / arsenal 不承担这四条玩法。#27 继续只做入口表面。
6. 主机测试只验机制。关卡好不好玩、通关第三关仍由 #15 人审。本调研不验手感。
7. 人审再报「还有 bug」时，规划先填本表分类，再开票。缺口先补合同，缺陷才重开实现线。
